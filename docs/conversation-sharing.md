# 会话导出与链接分享

## 本次范围

- Word：按当前会话中的正式消息即时生成 DOCX，响应直接下载。服务器不保存 DOCX，不提供文件七天留存、文件到期状态或断点续传。
- URL：用户主动创建公开的只读消息快照，有效期可选 7、14、21、30 天，默认 30 天。持有链接的人无需登录即可查看。后续消息不会自动进入已有快照；需要更新时先撤回，再创建新链接。
- 会话标题栏的“分享与导出”弹窗共用入口，但下载 Word 不会创建 URL 分享记录。
- 过期/撤回状态图标只代表 URL 分享。原 Issue #9 中的 DOCX 留存要求需要按此产品范围重新确认；代码实现不等于原 Issue 的全部验收项已满足。

## 数据流与撤回

1. 登录用户创建分享，后端检查会话所有权、运行状态及正式消息，保存标题与消息副本到 `workbench_conversation_shares`。不包含推理过程、工具事件或其他分支消息。
2. 每个会话最多保留一条当前分享记录。重复创建有效分享返回原链接；客户端创建请求使用 `Idempotency-Key`，旧请求重试不能重新激活已撤回的分享。
3. 公开页根据随机 token 读取快照；每次读取或检查状态都验证到期时间、撤回状态以及源会话/项目是否仍可访问。
4. 撤回以当前 token 为条件，防止旧标签页撤回刚重建的新链接。撤回立即清空数据库中的快照；删除会话或项目同样撤回。恢复回收站内容不会恢复公开访问。
5. 有效期到达时立即拒绝读取。后台约每十分钟清空过期快照，只保留供用户查看状态的小量元数据；这个清理周期不影响访问失效时点。

公开页每 15 秒检查状态，页面重新获得焦点/可见时也检查。发现链接失效后立即移除正文，三秒后返回配置的产品介绍页。检查失败或请求超过十秒时隐藏正文并允许重试。浏览器后台休眠可能推迟检查；撤回不能收回他人已经保存、复制或截图的内容。

匿名响应设置 `Cache-Control: no-store`，页面禁止搜索索引并设置 `no-referrer`。公开 Markdown 使用原有 HTML 清洗规则，外部图片显示为替代文字，不自动请求第三方图片。分享 token 本身就是读取凭据；部署时应限制访问日志的读取权限，并在反向代理日志中隐藏分享 URL 的 token。

## 关键文件

| 文件 | 作用 |
| --- | --- |
| `backend/workbench/conversation_export.py` | 正式消息筛选与内存 DOCX 生成；处理 XML 非法字符 |
| `backend/workbench/sharing.py` | 创建、状态、撤回、匿名读取与过期清理 |
| `backend/workbench/store.py` | 独立分享表；分享不进入通用内容列表、搜索或账号导出备份 |
| `backend/migrations/versions/20261029_conversation_shares.py` | 新分享表迁移 |
| `frontend/src/workbench/ConversationShare.tsx` | 分享与导出弹窗 |
| `frontend/src/workbench/SharedConversation.tsx` | 匿名只读页与失效检查 |

## 本地验收

沿用现有环境配置、数据库和账号。分享/导出本身无需调用模型，也无需重新配置 API key；已有正式消息即可测试。

从项目根目录运行 `pnpm run build`，再用原来的后端启动方式重启服务。打开现有本地地址，登录后进入会话，点击标题栏的“分享与导出”。数据库变更只有新增分享表，不更改账号角色或密码；需要显式执行 Alembic 的环境，应先按既有流程备份数据库，再在 `backend` 目录运行 `..\.venv\Scripts\python.exe -m alembic upgrade head`。

| 操作 | 预期结果 |
| --- | --- |
| 下载 Word，用 Word/WPS 打开 | 标题、正文、列表、表格与引用可读；服务器没有持久 DOCX 文件 |
| 创建七天链接，用未登录窗口访问 | 只读展示创建时的正式消息，不跳登录页 |
| 在源会话追加消息 | 已有链接的内容不变 |
| 保持公开页打开，原窗口撤回 | 公开页下一次检查后清空正文并跳回介绍页；旧链接接口返回 404 |
| 撤回后重新创建 | 得到新链接，旧链接仍不可访问 |
| 删除会话，再从回收站恢复 | 原公开链接仍不可访问 |
| 运行中、等待用户选择或空会话 | 不允许创建新分享或导出 |
| 在手机宽度打开弹窗和公开页 | 操作可见，表格可滚动，页面无整体横向溢出 |

自动化覆盖位于 `tests/test_workbench_conversation_export.py` 与 `tests/test_workbench_sharing.py`，并应同时运行原工作台/worker 回归。测试必须使用独立临时 `LAWVER_DATABASE_URL` / `LAWVER_TEST_DATABASE_URL`，不要指向个人或生产数据库，因为测试会重建表。

本次验证使用临时 SQLite 和 Chromium/Edge 浏览器；真实 PostgreSQL 并发、Android 原生分享面板、Word/WPS 实际排版仍需在对应环境验收。
