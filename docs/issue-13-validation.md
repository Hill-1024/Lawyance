## 部署验收模板

操作者在私有运行记录中填写环境标识、受测版本、结果与证据位置。公开清单保留
验收步骤；真实配置、密钥、数据版本细节、日志和具体环境执行记录留在运行环境。

- [ ] 记录受测服务与主应用的完整版本，校验交付摘要。
- [ ] 备份业务数据、附件和相关配置，并检查备份完整性。
- [ ] 在隔离候选目录验证配置准备：初始记录失败不改 `.env`；后续失败恢复旧 SHA/属主/权限；恢复失败保留资料并阻止重跑。成功须为 `phase: prepared` 且实际配置匹配新 SHA。
- [ ] 独立服务以专用账号启动，检查监听、可写目录、health 与 meta。
- [ ] 使用该环境批准的数据版本对照三个端点的正文和来源。
- [ ] 验证无密钥 401、禁用密钥 403、限流 429/Retry-After 与审计脱敏。
- [ ] 连续健康探测不新增用量审计；审计不可写时三个检索端点与鉴权 meta 仍拒绝返回，双探针告警；历史健康行不进入周报。审计 IP 按 TCP 直连对端地址解释，客户分析按 key 进行。
- [ ] 主应用以 remote 启动，实际调用三个法条工具，确认未扫描或构建本地法库。
- [ ] 验证独立 HTTPS 入口、证书校验及获授权客户端的三个工具调用。
- [ ] 检查客户镜像边界、新业务库迁移、页面、登录/退出与工作台读写。
- [ ] 使用实际配置完成对话验收和故障/恢复演练，记录通知与恢复路径。
- [ ] 验收用密钥完成测试后禁用；生产与巡检凭据按既定流程维护。

工作区语料仍完整，默认客户导出命令可以通过。新检出的本地法库从私有数据源同步，
见 [RAG/README.md](../RAG/README.md)。

无 Git 导出校验已有 manifest、哈希及成员集合，不从磁盘扩选源码。
验收时在临时工作区加入未跟踪的 `backend/private.py`、`frontend/src/private_token.ts`
等合成样本，确认不进入构建上下文、客户 ZIP 或镜像；篡改上下文或追加文件应被拒绝。
客户交付物与主仓历史分别核对，详见 [GitHub 协作说明](law-service-github-collaboration.md)。
该清单不表示所有部署环境已完成验收。credit 对接及其它后续项按 Issue #13 维护。
